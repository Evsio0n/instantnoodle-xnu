# OnePlus 8: public status, 2026-11-17

This publication summarizes evidence recorded through **2026-11-15** on one
OnePlus 8 IN2010 (instantnoodle, AMB655UV01 panel). It is a documentation update,
not a new device test or a downloadable firmware release. The installed build
is labelled **Daily 2026-11-15**; “daily” is a build label, not a claim that the
phone is ready to replace a normal daily-use phone.

## Daily build validation

The retained-data RAM preview (#596) and installed UFS boot (#597) each read
fresh factory calibration and accepted a completion marker belonging to the
current boot. This avoids accepting an old calibration-complete marker from
a previous boot. Factory calibration storage remained read-only.

Host checks included reproducing the known kernel baseline, ASan/UBSan checks
of the calibration-session and generated reader scope, a 948-entry root image
readback, bundle header/payload hashes, and five passing host checks. These
checks complement the device boot; they do not prove every feature or
long-term reliability. Installation details are a receipt, not instructions
for flashing another phone.

The installed kernel SHA-256 is
`0069be75b876d32e598728c2e1f54bcd74670b22e63ef474274655b17a1978c4`.
The full bundle SHA-256 is
`5788fd1be1a9594dba563884ea4d63bb3a77458fc8f94045441eda497bd67f28`.
The image contains private device/network material and is **not distributed**.
This documentation update does not add the latest integration source to the
public tree; the existing build instructions have not been requalified to
reproduce this installed bundle.

## AirDrop: partial experiment, paused

AirDrop is **not included in Daily**. Experimental RAM builds completed native
Mac → OnePlus text reception, including a saved file whose SHA-256 matched
the source. Earlier user reports also include OnePlus → iPhone delivery, but
this is not a stable bidirectional acceptance result.

A real iPhone photo of about 5.3 MB reached 100% upload progress but produced
zero completed file URLs and ended with CFHTTPServer error 1104. TCP receipts
alone do not establish HTTP/archive end-of-stream. Discovery also remains
intermittent. The final EOF observer did not receive a new photo, so neither
the exact root cause nor a fix was established. Multi-device, idle, lock and
reboot reliability are unqualified. Work was paused at the owner's request.

## What comes next

1. Metal frame pacing, memory growth and longer stability regression.
2. Wi-Fi across sleep, standby power, sensor DSP power release and charging/thermal qualification. System sleep stays disabled in Daily (`syssleep=0`).
3. Proximity, motion/rotation and an outdoor GNSS fix connected to native location services.
4. Call volume/routes, supplementary cellular services and full camera/media workflows.
5. Broader app installation, removal and persistence regression. Apple account, push, FairPlay and secure storage remain incomplete.

The [blog](https://shan.ink/posts/oneplus8-ios-feature-status/) has the feature
history and references. Historical measurements in the README remain dated
observations, not fresh benchmarks of Daily.
